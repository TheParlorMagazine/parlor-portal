# Cookie choices and GA4 collection

The approved white serif cookie banner is shared by Next.js pages and the standalone Trick or Treat page. Accept analytics and Reject optional have equal styling; preferences explain essential storage and an optional analytics switch. The footer and a persistent Cookie preferences button reopen it. First-party analytics and Google Analytics cookie storage stay off until an affirmative choice; Google Advanced Consent Mode may send cookieless measurement while consent is denied; malformed, future-dated or older-than-180-day choices are ignored. A versioned localStorage record contains only the choice and timestamp. DNT/GPC override opt-in. Essential authentication, cart and wishlist storage are not gated by this banner.

The existing page-view, live-presence and signed-in activity trackers are gated together. Rejection reduces the audience measured by the admin dashboard. A withdrawal immediately updates Google analytics consent to denied, clears known analytics identifiers and GA cookies, and reloads; Google's runtime can reload in denied mode; completed analytics events are not retroactively deleted. The standalone promotional page has the shared choices and gated first-party telemetry. This does not control unrelated third-party content embedded by authors; embedded services require their own review.

## GA4 setup

The reporting API and GA4 collection are separate. In Google Analytics select the intended property, then Admin → Data streams → the Web stream. Confirm the stream URL is the Parlor site. Copy its non-secret G-… Measurement ID into Netlify as NEXT_PUBLIC_GA_MEASUREMENT_ID for Production, with Builds scope. Redeploy. The numeric GOOGLE_ANALYTICS_PROPERTY_ID and private service-account JSON still configure only the report reader and must identify the same property. Never put the private JSON in NEXT_PUBLIC variables.

Next.js public pages preserve the existing AW-17582286057 Ads destination and optional configured GA4 destination, and load the Google tag in Advanced Consent Mode with a valid configured Measurement ID even before a choice or after rejection. A beforeInteractive bootstrap sets analytics_storage, ad_storage, ad_user_data and ad_personalization to denied before Google configuration, with wait_for_update of 500ms. The client initializer repeats that bootstrap idempotently as a fallback. Consent updates apply immediately on banner changes; only analytics_storage can become granted. DNT/GPC suppress Google collection entirely. ads_data_redaction is enabled and url_passthrough is disabled. Advertising storage, advertising user data and personalization remain denied. Admin, authentication, checkout and portal paths are excluded from GA4 page-view initialization. Explicit page locations omit query strings and fragments. The standalone static promotional page does not initialize the GA4 tag in this change. Google settings such as enhanced measurement should be reviewed separately; the runtime may collect additional events according to that stream's configuration once consent is granted.

Test using a browser without an analytics blocker: accept analytics on the public site, visit multiple pages, inspect GA4 Realtime and use Tag Assistant to confirm the destination G-… ID. Before opt-in or after rejection, the Google tag can send cookieless measurement pings but analytics_storage must remain denied and analytics cookies must not be created. First-party visitor, live presence and member-activity requests must be absent. In Tag Assistant inspect the Consent tab: default denied precedes config/page_view; Accept analytics updates analytics_storage to granted while all three advertising choices remain denied. Reopen preferences, reject optional analytics and confirm analytics cookie storage and first-party tracking stop after reload; Google cookieless measurement can continue. Standard GA reports can lag 24–48 hours. This does not backfill historical first-party visits into GA4, and its consent-filtered numbers need not match earlier dashboard totals.

## Verification

The consent browser test exercises the real notice and React analytics wrapper at desktop/mobile widths with mock network providers. It covers denied defaults before configuration, Google loading before opt-in without enabling first-party telemetry, rejection across reloads, opt-in, withdrawal and cookie cleanup, malformed/expired choices, GPC, and admin-page exclusion. Live GA4 ingestion requires the real Measurement ID and production deployment and is not established by local mock-provider tests.
