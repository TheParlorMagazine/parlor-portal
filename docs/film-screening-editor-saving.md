The screening editor has one Save changes action after the cover/trailer fields. The publish checkbox is next to that final action. Cover and trailer fields are submitted with ticket/event settings through the existing commerce workflow, validated before any mutation, and saved before Stripe synchronization and optional publication. Pause sales remains a separate explicit action.

Draft recovery is automatic browser-local storage, not a background change to published events or Stripe. Every valid field edit and completed upload URL is written immediately under a per-screening key; draft creation also preserves the submission UUID across retries and reopening. Drafts expire after seven days. The record contains only edited public event/media/settings fields; buyer information, Stripe IDs, access instructions and authorization notes are excluded. Publication choice is recoverable, but opening checkout always requires the final Save action. The UI states that a draft is saved on this browser and reports if storage is unavailable.

Successful saves clear the recovery draft. Validation, media or provider failures retain it, including when part of the server workflow already succeeded. Media updates use existing columns and do not require a migration. This is a retryable multi-step save, not a new database transaction: a media failure is explicitly reported before publication/Stripe synchronization continues. New screenings also recover drafts and retain their original creation ID, preventing duplicate creation after a failed retry. Close/escape/backdrop dismissal cannot discard completed edits; uploads and active saves continue to block closing the modal.
