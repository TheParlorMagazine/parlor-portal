# Newsletter Announcement editor

Only the newsletter Announcement block changes. The campaign editor, issue promotion, article/event/shop blocks, and support copy are unchanged.

The toolbar uses B, I, underlined U, a link icon, and an image icon. The image icon opens the existing upload/URL/media-library chooser inside the editor. A separate grid-style Insert album icon beside it opens the album picker directly; albums reuse the article editor’s picker and preview design with only 2-column, 3-column and masonry options. Carousel remains available in articles but is not offered in newsletter editing. For a single image, the chosen image is inserted at the current cursor without replacing selected text. Existing images appear in the canvas. Selecting an image exposes full-width, left-wrap, right-wrap and removal controls. Its position between paragraphs is saved directly, and it can be dragged within the editor. Removing it clears the separate image field so it cannot return on reload. Direct file drops upload at their canvas position and preserve text. Multiple dropped files become a 2-column album. Failed uploads preserve the announcement and allow retry; the shared album chooser also releases its uploading state on failure. The Done button matches the dashboard’s black primary-button styling.

Inline email styles and the image align attribute provide fallbacks; actual wrapping depends on the recipient's email client, particularly Outlook. No emails were sent during automated tests.

No migration is required. The existing issues.newsletter_announcement text column stores a versioned JSON envelope with kind newsletter_announcement. Version 1 retains html/layout/after compatibility; version 2 stores the original image node position and alignment in the canvas HTML. Version 3 also stores separately uploaded inline images and albums in that HTML. The original image source remains compatible with the existing newsletter_announcement_img field. Existing plain text continues through the original renderer until edited. Opening the editor upgrades its draft while preserving text; only Save announcement persists it. The same encoded value travels through the existing preview, test, review, send and retry paths. HTML is rendered server-side through a parser-backed allowlist: paragraphs, breaks, strong/emphasis/underline, safe links the original marked image node, marked uploaded-image nodes and album blocks. Original image nodes still use the separate announcement source; new inline media and albums accept only validated HTTP(S) image URLs and escape captions/alternative text. Other images, event handlers and executable content are discarded. Album output uses presentation tables: 2 or 3 columns for grids and two natural-height columns for masonry. No JavaScript or interactive carousel is included in email output.

Tests cover markup sanitization, unsafe links, plain-text compatibility, empty content, all layouts, unrelated newsletter content, editor formatting and links, image insertion without text loss, alignment reload and removal, desktop/mobile iframe previews and existing newsletter layout/test-email behavior.

Tests additionally cover direct drops, upload failure preservation, album insertion/edit-layout/reload, absence of carousel, styled Done buttons, validated inline image sources and email album rendering.
