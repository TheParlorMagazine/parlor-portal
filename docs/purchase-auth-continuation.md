# Resume purchases after authentication

Changes on `audit/parlor-production-readiness`; no additional SQL migration.

- Article/audio/video purchase intent is carried in `/checkout/article?articleId=…&stripePriceId=…&itemType=…`. Login/signup return destinations keep this URL, and the new page automatically requests Stripe checkout after authentication. The server still validates publication, stored price, identity and existing entitlement. Stripe success returns to the article using the existing paid-session verification; cancellation returns without granting access. React effect replay does not make duplicate checkout requests.
- The shop saves the delivery address for up to one hour in the initiating browser's local storage; the existing cart is already persisted there. On `/shop?checkout=1`, it waits for authentication and both catalog requests, restores the address and automatically opens Stripe. Loading products before bundles can no longer delete valid bundle entries or start a partial-cart checkout. Receipt/order confirmation still controls clearing the cart.
- Trick-or-Treat saves its selections in local storage for up to an hour, validates availability when restoring them and automatically continues to payment once all choices are present. Incomplete/unavailable selections remain for the user to repair.
- Email confirmation `/auth/confirm` now honors safe same-origin `returnTo` (or `redirect_to`), including a nested `/auth/callback?returnTo=…`, rather than always redirecting home. A short-lived destination cookie supports older templates omitting the destination, in the initiating browser. The regular OAuth/email callback has the same cookie fallback. Invalid confirmations never proceed to checkout; off-site destinations are rejected.

Operational limit: cart/address restoration requires the same browser/site storage. A verification email opened on another device cannot recover a browser-only shop cart. Configure Supabase email templates to forward the supplied RedirectTo URL and allow the site's `/auth/callback` URL, preserving its query string. No provider settings were changed or live emails sent. Templates which omit RedirectTo can resume via the destination cookie only in the originating browser; testing the actual production confirmation email is still required. Existing migrated-account password-setup links are a separate flow, unchanged here.

Validation: 120 unit/API tests passed; real-browser article/shop continuation passed (saved address, normal products plus delayed bundles, one API request under Strict Mode); actual Trick-or-Treat page automatic continuation passed; existing cross-site cart navigation suite passed. Production build passed with fake keys and local unreachable Supabase URL, as in the audit. No live purchases, emails, merges, production SQL or deployment performed.
